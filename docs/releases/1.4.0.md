# OpenDesk 1.4.0 — fundação V2

Release da fundação da arquitetura V2. O comportamento visível muda pouco; a
base interna foi reorganizada para destravar as ondas seguintes.

## Destaques

- **Domínio puro** (`opendesk-domain`): IDs tipados, `TaskStatus`, `RunStatus`,
  HITL 2.0, conversas, eventos e ports; sem SQL/HTTP/fs/Tauri.
- **Storage único** (`opendesk-storage`): baseline `0001_v2_baseline.sql` com
  **61 tabelas STRICT**, conversas/mensagens unificadas, pools de leitura,
  writer serializado, write-buffer e **todos os repositórios operacionais**
  (tasks, runs, queue, schedules, calendar, memory, io_bus, etc.).
- **Engine/recipes iniciados**: recorrência única, `worktree` e parser de
  receitas decompostos em módulos ≤500 linhas.
- **MCP/canais/enterprise iniciados**: rate/RBAC do MCP, domínio de canais +
  `NotificationRouter`, `mtls`/`update_signing` e virtual display.
- **Gate de limites**: falha para `.rs` >500 linhas ou `unwrap/expect` fora de
  testes; dívida legada fica em um baseline-ratchet.
- **Zero `expect` de produção nos crates** (locks recuperam de envenenamento,
  clients reqwest têm fallback).
- **CLI `opendesk-cli migrate-v1-export`**: exporta workspaces, receitas e
  settings de um banco V1 em JSON/YAML com manifesto SHA256, sem segredos.

## Mudança importante: banco V1

O V2 usa um baseline novo e **recusa abrir um banco V1** para não corromper
dados. Antes de subir a 1.4.0, exporte:

```bash
opendesk-cli migrate-v1-export --db ~/.local/share/opendesk/opendesk.db --out ~/opendesk-v1-export
```

Depois mova/renomeie o banco antigo e deixe o V2 criar `opendesk.db` novo. A
release 1.3.1 continua disponível para rollback.

## Segurança e integridade (desde 1.3.1)

- Webhook HTTP exige HMAC; `auto_execute` não roda sem segredo.
- IMAP sempre valida certificado.
- Merge de worktree overlay não sobrescreve edição do usuário; merge git exige
  índice limpo.
- Backup do SQLite faz checkpoint do WAL antes de copiar.
- Segredos só por `secret_ref` no cofre local.

## Desempenho

- Timeline incremental (lê só o que foi anexado), `run_log` com `seek`, cache
  do binário do OpenCode, `synchronous=NORMAL`, contador do chat isolado.

## Verificação

- **672 testes** (340 shell + 194 core + 79 storage + 27 domínio + 13 recipes +
  6 engine + 6 enterprise + 4 channels + 3 mcp).
- Clippy `--workspace --all-targets --all-features -D warnings`.
- `./scripts/gate.sh` verde: Playwright, goldens e cobertura **54,62% total /
  64,09% core** (pisos 53,8/62,7).
- Nenhum `.rs` novo acima de 500 linhas no storage; baseline de limites com 19
  god-files legados.

## Limitações conhecidas

- **Ondas 2–4 incompletas**: `queue_scheduler`, `opencode_client`, `adapters`,
  `dsh_router`, `run_export`/`run_timeline` e `recipes/{dag,store,engine,hitl}`
  ainda estão no core; a extinção de `opendesk-core` não aconteceu.
- Event-driven (`Notify`/`sleep_until`) e `kill_on_drop`/process group pendentes.
- Adaptadores reais de canal ainda no shell; WhatsApp/voz/computer-use
  Windows/macOS pendentes.
- Shell fino/frontend/doctor e a meta de 75% de cobertura pendentes.
- Release validada em **Linux**; MSI/NSIS e DMG exigem máquinas nativas.

## Instalação Linux

```bash
sudo dpkg -i opendesk_1.4.0_amd64.deb
# ou
sudo rpm -i opendesk-1.4.0-1.x86_64.rpm
sudo rpm -i opendeskd-1.4.0-1.x86_64.rpm
systemctl --user enable --now opendeskd
```
