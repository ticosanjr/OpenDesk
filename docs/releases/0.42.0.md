## OpenDesk v0.42.0

### MCP de controle operacional
- Novo MCP local `opendesk-control` (`opendesk mcp-control`) para agentes
  operarem tarefas, execuções, rotinas, receitas, fila, artefatos e atenção.
- Fala com a API local (`api.json` + bearer), reutilizando validação, eventos,
  fila e auditoria; não duplica execução.
- HITL, permissões e propostas de configuração são somente leitura.
- `opendesk-control` e `opendesk-config` são registrados em todo workspace, na
  criação e no boot para os existentes.

### Pacote base e operação
- Novo pacote `controle-opendesk` com skill `operacao-opendesk` e comandos
  `/opendesk-status`, `/opendesk-tarefa`, `/opendesk-rotina`,
  `/opendesk-receita` e `/opendesk-executar`.
- Instalado automaticamente em novos workspaces (manual, template e fábrica),
  sem sobrescrever arquivos existentes.
- Workspaces existentes recebem o MCP no boot; o pacote pode ser instalado em
  Pacotes.

### Rotinas e receitas nascem desligadas
- `schedules::create` sempre grava `is_active = false`; ativação é explícita.
- Receitas novas são gravadas com `enabled: false`; edições preservam o estado.
- Pacotes normalizam todas as receitas do bundle para desligadas.
- UI e formulários refletem o padrão e explicam como ativar.

### Refatoração e qualidade
- Handlers de sistema, health, meta, dashboard, workspaces, settings e
  middlewares extraídos de `api/mod.rs` para `api/core.rs` (863 → 538 linhas).
- Testes de starter packs em `starter_packs_tests.rs` (1939 → 1476 linhas).
- `GovernancePage` 1322 → 407, `AttentionCard` 867 → 518, `db/tasks.rs`
  968 → 853.
- Suíte funcional com manifesto de 68 capacidades, seed E2E, SMTP falso e
  `npm run test:features`; cobertura funcional 100% na última execução.
- Correção: promoção de aprendizado grava `requested_by = "learning"` por padrão.
