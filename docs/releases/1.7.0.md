# OpenDesk 1.7.0 — fim do `opendesk-core`

A 1.7.0 fecha o plano de melhorias: o crate `opendesk-core` deixa de existir.
Domínio, storage, engine, receitas, MCP, canais, enterprise e shell têm donos
claros; a baseline de limites de tamanho ficou vazia.

## Extinção do core

- Código restante distribuído:
  - backup, métricas, auditoria, passkey, integração com o desktop e a API
    interna agora vivem no shell;
  - chat, turnos, interações e mensagens de tarefa viraram repositórios em
    `opendesk-storage`;
  - manutenção do banco ficou no shell (`db::maintenance`), porque usa passkey;
  - `crate::db` virou uma fachada fina sobre `opendesk_storage::repos`.
- `opendesk-core` foi removido do workspace e de todas as dependências
  (`test ! -d src-tauri/crates/opendesk-core`).
- Nenhuma crate de negócio depende do shell; o shell importa diretamente
  domain/storage/engine/recipes/mcp/channels/enterprise.

## Fase 1 e 2 consolidadas

- Engine e receitas completos, sem god-files; fila dorme até o lease e cron usa
  a porta `ScheduledRecipeRunner`.
- MCP no crate `opendesk-mcp`; Telegram, Signal, WhatsApp, e-mail e Web Push no
  `opendesk-channels`, atrás de features; router de notificações no caminho real.
- Cluster e eval no `opendesk-enterprise`, com features validadas e probes reais
  no doctor (SQLite/WAL, sandbox, display, canais, mTLS).

## Frontend

- Todos os arquivos de produção ≤ 500 linhas.
- Chat com bolhas memoizadas e polling apenas como fallback dos eventos WS.
- AppShell fino (banner/notificações extraídos).

## Verificação

- `cargo check --workspace --no-default-features` e
  `cargo test --workspace --all-features` verdes.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings` limpo.
- Baseline de limites vazia; nenhum arquivo em `src-tauri/crates` > 500 linhas.
- Gate completo (Playwright + goldens) antes do release.

## Limitações

- Builds Windows/macOS e integrações que exigem telefone/QR ou áudio real
  continuam externos.
- A dívida de cobertura total do shell (CLI, tray, updater, doctor) segue como
  ratchet; o escopo de negócio fica acima da meta.
