## OpenDesk v0.43.0

### Assinatura de updates
- `latest.json` agora é assinado com Ed25519; o app embute a chave pública e
  recusa releases sem `latest.json.sig` válido.
- `scripts/release.sh` assina e verifica o manifesto antes de publicar.
- Novos comandos locais: `keygen-update`, `sign-update` e `verify-update`.
- Chave privada fica fora do repositório
  (`~/.config/opendesk/update-signing.key`, 0600); a pública é versionada.
- O fallback antigo que aceitava manifesto sem checksum foi removido.
- ADR 0045 e `docs/security/update-signing.md`.

### MCP de controle
- `routine_create` e `routine_update` aceitam todos os gatilhos:
  `CRON`, `FOLDER_WATCH`, `RSYNC_FOLDER`, `IMAP_IDLE`, `SIGNAL_MSG`,
  `WEBHOOK` e `SQL_POLL`.
- `trigger_config` (objeto) e `trigger_config_json` (texto) são aceitos;
  rotinas CRON continuam exigindo `recurrence` ou `cron_expression`.
- Novas ferramentas: `task_message_list`, `task_message_post`, `artifact_pin`
  e `artifact_rollback`.
- Rotinas continuam nascendo desligadas.

### Ativação explícita
- Ativar rotina ou receita pela UI agora pede confirmação com consequências e
  permite cancelar.

### Contrato Google
- Script opt-in `npm run contract:google` valida status, MCP Google e uma busca
  read-only no Drive; não cria nem apaga documentos.

### Segurança do Browse
- Tarefas com `needs-browser` podem declarar
  `browse-allowlist:dominio1,dominio2`.
- A UI ganhou o campo **Domínios permitidos** no formulário de tarefa.
- O prompt do Browse recebe a allowlist e instrui `session_allowlist` com os
  domínios exatos.
- Tarefas de alto risco (`browse-high-risk`, `browse-login`,
  `browse-payment`, `browse-banking`, `browse-2fa`) são bloqueadas no dispatch
  sem allowlist válida.

### Observabilidade operacional
- Dashboard mostra quantas rotinas estão ativas e quantas receitas estão
  habilitadas, com links diretos para revisão.
- `opendesk doctor` reporta cobertura do MCP `opendesk-control` e do pacote base
  por workspace, com avisos acionáveis.

### Acessibilidade
- Auditoria axe nas rotas principais e no modal de tarefa, com gate para
  violações críticas **e sérias**.
- Contraste corrigido: zinc-500 mais claro, textos zinc-600/700 eliminados e
  botão de acento mais escuro para texto branco.
- Quadro Kanban virou região focável e rolável por teclado.
- Botão do workspace ativo agora inclui o nome visível no nome acessível.

### Refatoração
- Loop JSON-RPC dos MCPs extraído para `mcp_server.rs`; `opendesk-config`,
  `opendesk-control` e `opendesk-google` agora compartilham o mesmo protocolo.
- `mcp_control.rs` dividido em `tools.rs` (schemas), `payload.rs` (payloads) e
  `util.rs` (argumentos/URL), caindo de ~1250 para 569 linhas no módulo
  principal.
- `api/tasks.rs` 953 → 742 linhas com `task_dispatch.rs` (dispatch, roteador,
  fila e browser).
- `starter_packs.rs` 1502 → 1317 linhas com `plan.rs` (manifesto e
  planejamento de arquivos/rotinas).
- Sem mudança de comportamento; smoke test confirmou `opendesk-control` com 23
  ferramentas.

### Qualidade
- ESLint com regras de React Hooks e TypeScript no `check:changed` e no gate.
- Corrigidos 6 efeitos com dependências faltantes e um trecho de código morto.
- Testes de digitação real (`pressSequentially`) em tarefa, workspace, evento e
  rotina, cobrindo a classe de bug do foco.
- `npm audit --omit=dev` limpo; override de `dompurify` para 3.4.17.
- Testes de assinatura: válida, manifesto adulterado, `key_id` desconhecido,
  algoritmo inválido e round-trip de chave.
- Testes do MCP para gatilhos não-CRON e atualização de configuração.
- Testes: **345 Rust**, **131 Vitest** e **72 Playwright**.
- Cobertura funcional: **69/69 features (100%)**.
