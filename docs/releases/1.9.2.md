# OpenDesk 1.9.2 — recuperação de SQLite e Telegram

Correções de confiabilidade depois do 1.9.1.

## SQLite

- O reparo automático não depende mais do binário externo `sqlite3`.
- Se `VACUUM INTO` falhar, o OpenDesk cria um schema novo pelas migrations e
  copia tabela/coluna por tabela via `ATTACH`, com janelas de `rowid` para
  contornar páginas corrompidas.
- O banco reparado só substitui o original após `PRAGMA integrity_check = ok`.
- O backup `.corrupt-*` continua sendo criado antes de qualquer alteração.

## Telegram

- **Iniciar bot** agora habilita a integração automaticamente; antes ele podia
  falhar silenciosamente quando o checkbox não havia sido salvo.
- O checkbox da UI sincroniza com o estado real retornado pela API.
- O erro de “nenhum chat conhecido” agora distingue integração desabilitada,
  bot parado e bot ativo sem mensagem recebida.
- O fluxo esperado permanece: habilitar/salvar, iniciar o bot e enviar `/start`
  pelo celular usando o `@username` ou chat ID da allowlist.

## Qualidade

- Testes e clippy do `opendesk-storage` e do módulo Telegram.
- Verificação proporcional do release e gate completo anterior preservados.
