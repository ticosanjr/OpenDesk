# OpenDesk 0.55.0

Release de correções do Folder Watch e do chat: arquivos monitorados não são
mais reprocessados sem alteração, e o Telegram finalmente responde à pergunta
atual em vez de repetir a resposta anterior.

## Folder Watch sem duplicatas

- Estado persistente por receita/gatilho/arquivo em `recipe_file_state`
  (migração 0036).
- Fingerprint `mtime` em nanossegundos + tamanho: o arquivo só volta a ser
  processado quando muda.
- Reiniciar o OpenDesk não reprocessa arquivos já tratados.
- `process_existing=false` marca os arquivos existentes como vistos, sem
  executá-los.
- Falha ao **iniciar** uma execução ainda pode ser tentada novamente; run que
  terminou `FAILED`, `REJECTED` ou `TIMED_OUT` mantém o fingerprint e só volta
  quando o arquivo muda.
- No primeiro scan após a atualização, arquivos já presentes em `recipe_runs`
  são conciliados para evitar uma última reprocessação em massa.

## Chat e Telegram no turno certo

- O chat agora registra o instante do prompt e aguarda o turno novo do
  OpenCode (`idle`/estabilidade) antes de ler a resposta.
- Apenas mensagens `assistant` criadas depois do prompt entram na resposta.
- Se o modelo ainda não respondeu, o OpenDesk espera; nunca reutiliza a saudação
  ou a resposta antiga.
- Timeout de 5 minutos retorna erro claro em vez de conteúdo obsoleto.
- Tokens e custo são somados apenas do turno atual.
- O histórico continua na sessão do OpenCode; o OpenDesk não reenvia o histórico
  inteiro a cada mensagem.

## Verificação

- `npm run verify` verde.
- 421 testes Rust e 222 Vitest.
- Testes novos cobrem fingerprint/estado persistente, conciliação de runs
  antigos, resposta antiga vs. turno novo e polling com fake OpenCode.
- Teste manual pendente: bot real com duas perguntas diferentes e uma pasta
  monitorada com reinício/alteração de arquivo.

## Notas

- A migração 0036 é aplicada automaticamente no primeiro start.
- Arquivos cujo conteúdo muda preservando exatamente mtime e tamanho não são
  detectados pelo fingerprint; é um caso raro.
- O campo “Retentar falha de início” agora deixa claro que ele não reprocessa um
  arquivo que já rodou e falhou.
